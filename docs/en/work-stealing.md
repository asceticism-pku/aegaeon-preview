# Decode Work Stealing

This optional load-balancing mechanism is disabled by default. Within one Controller, an idle Decode Engine can receive an entire unstarted batch from another Scheduler.

## Enable Work Stealing

```yaml
server:
  num_engines: 0
  num_prefill_engines: 1
  num_decode_engines: 2
  decode_work_stealing: true
  decode_work_stealing_min_batch_gap: 2
```

At least two Decode Engines are needed for transfers. The gap must be >=2.

## Transfer conditions

A donor attempts at most one transfer after a round completes. The receiver must be completely idle. Eligible candidates are non-head, never-started (start_time is None), complete BatchedRequests with KV state logically resident on CPU. Candidates matching the receiver's resident model are preferred.

Owner, queues, load gap, and KV state are rechecked before transfer. Critical queue mutations contain no await; failed checks leave queues unchanged. Batches already started or inside an Engine pipeline are not moved. Transfers do not cross Controllers or physical nodes.

## Metrics

Runtime work_stealing includes enabled, gap, attempts, successes, and rejection. decode_load includes per-Engine tokens, active_seconds, steps, rounds, turns, switches, transfer counters, and CV.

Decode output_tokens excludes the first token generated by Prefill. active_seconds measures wall time from dispatch until the Worker returns, not pure kernel time. CV is population standard deviation divided by the mean. Compare identical engine sets and workloads.

## Paired validation

```bash
CUDA_VISIBLE_DEVICES=0,1,2 python benchmark/work_stealing_gpu_smoke.py \
  --model-paths /srv/models/model-a /srv/models/model-b \
  --work-stealing off --result-file /tmp/ws-off.json
CUDA_VISIBLE_DEVICES=0,1,2 python benchmark/work_stealing_gpu_smoke.py \
  --model-paths /srv/models/model-a /srv/models/model-b \
  --work-stealing on --result-file /tmp/ws-on.json
python benchmark/compare_work_stealing_results.py /tmp/ws-off.json /tmp/ws-on.json
```

Replace model-a/model-b with real compatible checkpoints that satisfy the script's prerequisites. Run the two cases sequentially to avoid GPU contention. The comparison tool checks workload, Engine set, output lengths, and token conservation.

## Limitations

Work Stealing triggers only when a completely idle Decode Engine is available and moves one complete, unstarted batch at a time. A cross-model move adds a model switch. The results in `docs/work-stealing.md` come from the small constructed workload described there.
