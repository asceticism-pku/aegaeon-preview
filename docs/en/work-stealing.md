# Decode Work Stealing

This optional load-balancing mechanism is disabled by default. Within one Controller, a Decode Engine with an empty batch queue can receive an entire eligible waiting batch from another Scheduler.

## Enable Work Stealing

```yaml
server:
  num_engines: 0
  num_prefill_engines: 1
  num_decode_engines: 2
  decode_work_stealing: true
  decode_work_stealing_min_batch_gap: 2
```

At least two Decode Engines are needed for transfers. The gap must be >=2.

## Transfer conditions

A donor attempts at most one transfer after a round completes. The receiver's batch queue must be empty. Eligible candidates are non-head, complete BatchedRequests with `start_time is None` and KV state logically resident on CPU. `start_time` resets after every iteration, so the condition means no iteration is currently in flight; a waiting batch that has already generated tokens can qualify. Candidates matching the receiver's resident model are preferred.

Owner, queues, load gap, and KV state are rechecked before transfer. Critical queue mutations contain no await; failed checks leave queues unchanged. Batches with an iteration in flight are excluded. Transfers do not cross Controllers or physical nodes.

## Metrics

Runtime work_stealing includes `enabled`, `min_batch_gap`, `attempts`, `successes`, and `rejections`. decode_load includes per-Engine `output_tokens`, `active_seconds`, `decode_steps`, `rounds_completed`, `turns_completed`, `model_switches`, transfer counters, current queue load, and CV.

Decode output_tokens excludes the first token generated by Prefill. active_seconds measures wall time from dispatch until the Worker returns, not pure kernel time. CV is population standard deviation divided by the mean; the implementation returns 0 for empty input or a zero mean. Confirm that counters contain actual work before interpreting balance, and compare identical engine sets and workloads.

## Paired validation

```bash
CUDA_VISIBLE_DEVICES=0,1,2 python benchmark/work_stealing_gpu_smoke.py \
  --model-paths /srv/models/model-a /srv/models/model-b \
  --work-stealing off --result-file /tmp/ws-off.json
CUDA_VISIBLE_DEVICES=0,1,2 python benchmark/work_stealing_gpu_smoke.py \
  --model-paths /srv/models/model-a /srv/models/model-b \
  --work-stealing on --result-file /tmp/ws-on.json
python benchmark/compare_work_stealing_results.py /tmp/ws-off.json /tmp/ws-on.json
```

model-a/model-b are placeholder paths. The script's `build_config()` budgets for A100 80 GiB and two parameter counts of `0.6 × 2^30` and `7.1 × 2^30`. Both default profiles are `qwen2_5_7b`; `--profiles` and `--device-profile` select explicit aliases. The default prompt has 16384 tokens, and the model context must also accommodate the output. For other models or devices, first check and adjust the script's parameter counts, device capacity, and memory budgets and prepare matching profiles. Run the two cases sequentially on dedicated GPUs. The comparison tool checks request IDs, model names, input/output lengths, Engine sets, and Decode token conservation.

## Limitations

Work Stealing triggers only when a Decode Engine has an empty batch queue and moves one complete eligible waiting batch at a time. A cross-model move adds a model switch. The paired test uses a constructed workload; evaluate throughput, latency, and balance from retained raw results.
